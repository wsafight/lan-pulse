# LanPulse 优化路线图

## 1. 文档说明

本文记录 LanPulse 从当前可运行版本走向稳定、低延迟、安全且可发布产品所需的工作。

状态标记：

- `[x]` 已完成：代码已经实现，并通过自动化构建或测试。
- `[~]` 部分完成：已有可用实现，但仍缺少关键能力或真机数据。
- `[ ]` 未完成：尚未实现，或没有足够证据确认完成。

当前优先顺序：

1. 完成 Linux 到 Android 的真机端到端验证。
2. 补齐关键音频指标，并用真机长时间数据校准已实现的自适应抖动缓冲和时钟漂移修正。
3. 补齐 Android MediaSession、音频焦点和网络感知重连。
4. 完成可信设备、PIN 过期和媒体加密。
5. 再进行安装包发布、其他桌面平台和 iOS 扩展。

## 2. 当前基线

### 2.1 桌面端

- `[x]` Rust 后台服务和原生桌面壳。
- `[x]` Linux 通过原生 PipeWire API 捕获系统输出，失败时可回退测试音。
- `[x]` 音频捕获使用独立线程，不在 Tokio 工作线程内执行阻塞读取。
- `[x]` PipeWire 实时回调使用预分配 PCM 缓冲池和双向 SPSC 环形队列，不创建子进程，不在逐包热路径分配内存。
- `[x]` 捕获队列有容量上限；积压时丢弃音频并推进 RTP 序号和时间戳，避免延迟无限增长。
- `[x]` 默认发送 PCM s16le、48 kHz、双声道、5 ms RTP 包。
- `[x]` 默认 RTP 包低于常见 IPv4 MTU，避免 IP 分片。
- `[x]` 在 `41000..41020` 范围进行 UDP 局域网发现。
- `[x]` 控制端口默认在配置范围内自动选择。
- `[x]` HTTP PIN 连接、状态查询和设备断开接口。
- `[x]` 单接收端占用保护：另一台手机连接时明确拒绝，不静默顶替。
- `[x]` 同一台手机可重连并更新 UDP 端口。
- `[x]` 使用 `client_id` 和 `session_id` 防止旧会话的迟到断开请求误伤新会话。
- `[x]` 系统托盘、服务启停、二维码、设置、日志、诊断和设备断开。
- `[x]` 桌面端中英文切换，首次默认英文并记忆选择。
- `[x]` RTP packetizer 复用发送缓冲区，不再为每个 5 ms 包创建新 `Vec`。
- `[ ]` Windows WASAPI 回环捕获。
- `[~]` macOS ScreenCaptureKit 系统音频捕获已实现并通过编译；本机 TCC 未授权，待完成真实音频端到端验证。

### 2.2 Android

- `[x]` KMP/Compose 应用结构。
- `[x]` 自动发现桌面端并支持手动输入控制地址。
- `[x]` CameraX 相机预览和 ZXing 纯 JVM 离线二维码识别。
- `[x]` 校验 `lanpulse://pair`、本地 IPv4 地址和 PIN 格式。
- `[x]` 首次默认英文，支持中文和英文并持久化用户选择。
- `[x]` RTP 版本、负载类型、SSRC、包长度和扩展头校验。
- `[x]` RTP 序号跟踪、乱序窗口、重复包过滤和序号回绕处理。
- `[x]` 发送端序列重启后清空旧窗口并重新缓冲。
- `[x]` 默认 5 ms 包下使用 15 ms 初始自适应缓冲，稳定网络下降至 10 ms，抖动时最高增至 60 ms；其他包时长按至少两个完整包向上取整。
- `[x]` 使用 RTP 时间戳和到达时间估算网络抖动；underrun 后快速扩容，稳定后缓慢收缩。
- `[x]` 预分配 RTP 包池、SPSC 接收/回收队列和固定槽乱序窗口；正常逐包路径不分配或额外复制 payload，漂移修正复用预分配输出缓冲。
- `[x]` 跟踪 AudioTrack 播放头和队列深度，通过每包最多增减一个 PCM 采样帧修正短期时钟漂移。
- `[x]` 最大 80 ms 网络积压限制。
- `[x]` 缺包时插入静音，积压过大时跳到接近实时位置。
- `[x]` AudioTrack underrun 触发重新缓冲。
- `[x]` 使用专用高优先级音频线程和低延迟 AudioTrack。
- `[x]` AudioTrack 使用阻塞完整写入，不丢弃部分写入的数据。
- `[x]` 限制采样率、声道、包时长、RTP 负载类型和最大包尺寸。
- `[x]` `mediaPlayback` 前台服务和持续通知。
- `[x]` 播放期间持有局部唤醒锁和高性能 Wi-Fi 锁。
- `[x]` 可重试错误三秒后自动重连；离线时通过 Android 网络回调等待网络恢复，恢复后立即重试。
- `[x]` 显示接收包、丢包、目标缓冲、实际 AudioTrack 队列、网络抖动和 underrun 指标。
- `[x]` 扫码不依赖 Google Play 服务，APK 不再包含四套 ML Kit 原生识别库。
- `[x]` 已检测并展示 AudioTrack underrun 计数。
- `[~]` MediaSession、锁屏播放控制和耳机按键控制已接入基础停止控制；暂停/继续仍待状态机支持。
- `[~]` 音频焦点和输出设备切换处理已接入失焦/输出移除停止策略；仍待更多路由变化真机验证。
- `[ ]` 真机前台、后台、锁屏、延迟、温度和耗电完整验证。

- 记录手机型号、Android 版本、路由器、CPU、温度和耗电。

- 在测试构建或脱敏诊断中记录目标缓冲、实际队列深度、网络抖动、捕获/接收队列溢出、缓冲池耗尽、迟到、乱序、重复、补偿和 underrun。
- 记录漂移插帧/丢帧次数、修正速率以及队列深度 P50/P95/P99。

完成标准：

- 稳定网络下实测延迟达到 `20..50 ms`，并记录测试条件。
- 1% 随机丢包下播放不中断连接。
- 缓冲不会随播放时间持续增长。
- `100/500/1000 ms` 网络暂停后能够自动恢复，且不会持续播放过期音频；从网络恢复开始计算，目标恢复时间小于 1 秒。
- 显式断开后不会自动重连。

### 3.2 自适应抖动缓冲 `[~]`

已完成：

- 根据 RTP 时间戳和本地到达时间计算 RFC 3550 风格的实时网络抖动。
- 默认 5 ms 包下初始目标 15 ms，稳定网络收缩到 10 ms，抖动网络逐步增长到最多 60 ms；其他包时长按至少两个完整包向上取整。
- 最大 80 ms 积压限制和接近实时重置。
- RTP 乱序恢复、缺包静音和序列重启恢复。
- AudioTrack underrun 检测、目标缓冲快速增长和重新缓冲。
- 网络恢复后需持续稳定 5 秒才逐档缩小，避免频繁振荡。
- Android 统计网络抖动、迟到包、重复包、接收队列溢出、缓冲池耗尽、AudioTrack underrun 和漂移插帧/丢帧次数。
- 对应的稳定网络、变动到达时间和 underrun 自动化测试。

待完成：

- 提供低延迟、均衡、稳定三种策略。
- 面向用户的脱敏诊断导出中加入迟到、乱序、重复、队列丢弃、静音补偿和本地 underrun。
- 用不同品牌真机和不同路由器校准扩容、收缩阈值。

### 3.3 时钟漂移和音频调度 `[~]`

已完成：

- 使用 RTP 时间戳参与网络抖动和媒体时钟判断。
- 跟踪 AudioTrack 32 位播放头，处理回绕并计算真实排队帧数。
- 队列偏深时每个 RTP 包最多移除一个 PCM 采样帧。
- 队列偏浅时每个 RTP 包最多插入一个线性插值 PCM 采样帧。
- 不通过整包跳跃修正漂移，降低可听见断音风险。

待完成：

- 真机连续播放 30 分钟，记录队列深度、漂移修正频率和可听质量。
- 使用合成采集/播放时钟覆盖 `±50/±100/±300 ppm`，验证 30 分钟内队列深度保持有界。
- 为插帧/丢帧设置最大修正速率，并验证异常队列深度不会触发过密修正。
- 使用静音、正弦波、脉冲和真实音乐验证插帧/丢帧不会产生明显爆音。
- 只有逐帧修正不足或可听时，再使用轻量重采样器处理长期采集/播放时钟偏差。
- 对比 AudioTrack 与 Oboe/AAudio 的真机延迟和 underrun 数据。

完成标准：

- 连续播放 30 分钟后缓冲深度仍有界。
- 漂移修正没有可听见的爆音或周期性断音。

### 3.5 媒体认证和加密 `[ ]`

当前 RTP PCM 仍为明文，不能宣称媒体链路安全。

待完成：

- 每个播放会话派生独立媒体密钥。
- 使用 ChaCha20-Poly1305 或 AES-GCM 认证并加密媒体包。
- 将序号、时间戳、SSRC 和会话 ID 放入认证数据。
- 定义 nonce 和序号回绕规则。
- 拒绝重复、重放、篡改和跨会话数据包。
- 加密后默认 5 ms 包仍低于常见路径 MTU。

### 3.6 Android 播放生命周期 `[~]`

已完成：

- 前台播放服务、通知断开操作和明确状态。
- Wake Lock、Wi-Fi Lock 和三秒重连。
- 应用任务被移除后服务不随任务自动停止。
- 显式断开会取消播放任务并释放资源。
- 使用 MediaSession 将连接、播放、重连、失败和停止映射为系统播放状态。
- 通知栏、锁屏、蓝牙/有线耳机媒体按键可触发停止并释放播放资源。
- 获得音频焦点后启动播放；暂时或永久失去焦点时停止播放。
- 检测输出设备移除并停止播放，避免继续向无效输出写入音频。
- Android 网络回调区分离线与桌面端故障；离线时等待网络恢复，恢复后立即进入重连流程。
- Android 重连复用当前 `session_id`，避免长时间播放后被一次性 PIN 过期阻断；显式停止和不可恢复错误仍会主动断开桌面会话。

待完成：

- 明确区分暂停与断开：暂停保留当前连接上下文，断开释放网络和播放资源。
- 扬声器、耳机、蓝牙和 USB 输出路由切换后的继续播放策略。
- 对非离线的服务端故障增加有上限的指数退避。
- 明确定义进程被杀后的恢复行为，避免意外自动播放。

完成标准：

- App 内、通知栏、锁屏和系统媒体面板显示的状态始终一致。
- 暂停、继续、停止、耳机按键和音频焦点事件遵循同一状态机。
- 用户主动断开后，系统播放键、MediaSession 恢复或快捷入口不能绕过配对并自动发声。

### 3.7 协议版本和能力协商 `[~]`

已完成：

- 在发现响应和连接响应中携带当前协议版本、最低兼容版本和能力标志。
- Android 发现阶段过滤不兼容桌面端。
- 桌面端连接阶段拒绝显式不兼容客户端并返回 `426 Upgrade Required`。
- Android 控制客户端将协议不兼容视为不可重试错误，不进入媒体传输阶段。
- 为版本范围重叠、发现响应、连接请求和不兼容响应添加自动化测试。

待完成：

- 为媒体加密、Opus、FEC、多接收端和同步播放定义独立能力标志，不仅依赖应用版本号。
- 明确版本升级、未知字段、缺失能力和降级行为。
- 扩展新旧客户端和服务端的兼容测试矩阵。

完成标准：

- 新旧客户端和服务端的兼容组合具有自动化测试矩阵。
- 不兼容版本不会错误播放、无限重连或静默降级到不安全模式。

## 8. 产品约束

- 未实现媒体加密前，不宣称音频传输安全。
- 没有声学测量和测试条件时，不宣称具体端到端延迟。
- 不为功能数量牺牲第一版固定格式的稳定性。
- 开机播放和自动发声必须默认关闭。
- 不记录 PIN、设备密钥、会话密钥或解密后的媒体内容。
- 任何快捷入口都不能绕过配对和设备占用检查。
- 协议不兼容时必须明确失败，不能无限重连或静默降级安全能力。
- 加密后默认 5 ms 包仍必须低于常见路径 MTU。
